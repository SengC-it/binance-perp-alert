# 币安永续合约信号提醒（只提醒，不代下单）

一个**只读、单用户、自托管**的信号提醒守护进程。它只告诉人「现在有什么值得看」，
**是否开仓、开多少、何时平仓，全部由人决定**。系统不接触任何执行类接口。

管两件事：

1. **持仓风险**（每 30 秒）：读取你的币安 U 本位合约账户，计算强平距离、保证金率、资金费成本、
   组合风险敞口与回撤，命中规则后发邮件 / Telegram。
2. **机会与信号扫描**：扫描全市场永续的资金费率与基差，折算成**扣费后的净年化收益**；
   另有截面低波动调仓信号。过滤掉流动性不足的合约后推送。

## 范围声明：零执行

本系统**不具备**下单、改单、撤单、调整杠杆与保证金、资金划转、提现的能力。
它只能读取公开行情和你账户的只读快照，然后把结论发到你的邮箱或 Telegram。

这不是口头承诺，而是**代码级可验证的不变量**：

```bash
python main.py audit
```

自检扫描全部自有源码（38 个 .py），检查 12 个禁用端点、11 个执行类标识符，
并确认 HTTP 动作**仅为 GET**。任何一处越界都会让命令返回非零退出码；
`tests/test_scope_guard.py` 会在测试中同步拦截。

自检刻意**不读取配置、不导入被检查模块**（纯文本匹配），因此它能在配置损坏、
依赖缺失、无网络的环境下运行——一个需要先信任配置才能运行的检查，不能用来证明边界。

因此请使用**只读 API Key**，并同时开启 IP 白名单（见「三、配置币安只读 API Key」）。

## 为什么是自研

2026-09-12 的调研结论（详见 `../binance-perp-playbook/ALERT_SYSTEM_RESEARCH.md`）：
GitHub 上**不存在**现成的"合约/套利交易邮件提醒系统"。Freqtrade（54k★）与 Hummingbot（20k★）
都只有 Telegram/Discord，没有邮件通道；现成的资金费提醒项目全部是 0–3 星的 Telegram 玩具。
唯一现成的 Webhook→邮件桥梁 `fabston/TradingView-Webhook-Bot` 依赖 TradingView，而 TradingView 没有资金费数据。

因此本项目：**复用成熟组件 + 只自研缺失的部分**。

| 层次 | 来源 |
|---|---|
| 投递层 | 复用 `caronc/apprise`（BSD-2，17.3k★） |
| 数据层 | 直接调用币安官方 REST（见下方"设计取舍"） |
| 计算层 / 规则层 / 状态层 | 自研（本仓库） |

### 设计取舍：为什么没用 ccxt

调研报告里我推荐了 `ccxt`，实际实现时改成了直连币安 REST，理由有三：

1. 需求已明确**只做币安**，跨所抽象层用不上，反而多一层依赖；
2. 本系统需要 `maintMargin`、`liquidationPrice`、`leverage` 这类**交易所特有字段**，统一抽象层反而会削掉细节；
3. 这个进程持有你的 API 密钥，**依赖越少越容易审计**。签名逻辑只有约 10 行（`hmac` + `hashlib`，标准库）。

`ccxt` 会在 Phase 2 增加跨所扫描时引入，那时抽象层的价值才成立。

## 二、配置 Gmail 发信（关键步骤）

Gmail **不允许**用账号主密码做 SMTP 认证，必须使用"应用专用密码"。

**步骤：**

1. 开启两步验证：<https://myaccount.google.com/security> → "两步验证" → 按提示完成。
2. 生成应用专用密码：<https://myaccount.google.com/apppasswords>
   - 应用名随便填（如 `Work Alert`），生成后得到 **16 位密码**。
   - 页面上会显示成 `abcd efgh ijkl mnop` 的样子，**填写时要把空格去掉**。
3. 复制 `.env.example` 为 `.env`，填写：

```ini
APPRISE_URL=mailtos://你的gmail用户名:16位应用密码@gmail.com?to=收件邮箱@example.com
```

要点：

- `mailtos://` 走 SSL（465 端口）；如果网络环境屏蔽 465，改用 `mailto://`（587 + STARTTLS）。
- 收件人可以多个，用逗号分隔：`?to=a@x.com,b@y.com`。
- 收件人**不一定要是 Gmail**，任何邮箱都可以；发信方必须是 Gmail。

4. 验证链路：

```bash
python main.py test-email
```

收到邮件即成功。没收到请依次检查：应用专用密码是否正确（去掉空格）、两步验证是否开启、
垃圾邮件目录、以及 `.env` 是否被正确读取（用 `--verbose` 看日志）。

**Gmail 的限额与注意点**

| 项目 | 说明 |
|---|---|
| 免费 Gmail 发信限额 | 约 500 个收件人/天。本系统默认每小时最多 12 封，远低于限额 |
| 发件人显示 | 始终是你的 Gmail 地址，Gmail 会改写 From 头 |
| 送达率 | 由 Google 处理 SPF/DKIM，通常直接进收件箱 |
| 风控 | 从 VPS 的新 IP 发信可能触发 Google 的异常登录提醒，属正常现象 |
| 建议 | 给这类邮件建一个 Gmail 过滤器 + 标签，并标记为重要，避免淹没在日常邮件里 |

> 如果以后告警量变大或需要自定义发件域名，升级路径是换成事务性邮件服务
> （Resend / Postmark / SendGrid / AWS SES），**只需改 `APPRISE_URL` 一行，代码不用动**——
> 这正是选 Apprise 的原因。

## 三、配置币安只读 API Key

1. 币安 → API 管理 → 创建 API。
2. 权限**只勾选"允许读取"**。不要勾选"允许合约交易"，更不要勾选"允许提现"。
3. 开启 **IP 白名单**，只填你运行本程序的机器 IP。
4. 填入 `.env`：

```ini
BINANCE_API_KEY=你的key
BINANCE_API_SECRET=你的secret
```

> 用只读 Key 时，即使密钥泄露，攻击者也无法转移资金或开仓。
> 这是本系统"只读"设计的全部意义。

## 四、配置规则

```bash
cp config.example.yaml config.yaml
```

必须改的地方：

1. **`symbols`** —— 填入你实际交易的标的与**计划止损距离**。
   这是计算 1R 金额和"强平距离/止损距离"倍数的基础。未配置的标的会跳过相关规则。

```yaml
symbols:
  BTCUSDT:
    planned_stop_pct: 2.0      # 你的计划止损距离，2%
  ETHUSDT:
    planned_stop_pct: 2.5
```

2. **`thresholds`** —— 阈值建议与 `TRADING_PLAN_TEMPLATE.md` 第 4 章保持一致。
   默认值已经按那份计划书设定，例如 `liq_to_stop_min_ratio: 3.0` 就对应
   "强平距离必须 ≥ 3 倍止损距离"的杠杆上限规则。

python main.py check-config    # 校验配置，不联网、不发邮件

**强烈建议先跑 3 天 `--dry-run`**，看日志里"告警进入每日摘要队列"的频率，
确认规则阈值不会把你淹掉，再切换到正式发送。

## 六、规则清单

| 规则 ID | 默认分级 | 默认确认次数 | 触发条件 |
|---|---|---|---|
| `liq_distance_insufficient` | CRITICAL | 2 | 强平距离 < 3 × 计划止损距离 |
| `margin_ratio_low` | WARN / CRITICAL | 3 | 保证金率 ≥ 60%（≥80% 升级为 CRITICAL；100% 即强平） |
| `funding_cost_high` | WARN | 3 | 累计资金费成本 ≥ 0.30R |
| `portfolio_heat_exceeded` | WARN | 3 | 全部持仓止损同时触发时风险 > 4% 权益 |
| `daily_loss_limit` | WARN / CRITICAL | 2 | 当日亏损 ≥ 2%（≥3% 升级为 CRITICAL） |
| `drawdown_stop` | CRITICAL | 1 | 自峰值回撤 ≥ 20% |
| `heartbeat_stale` | CRITICAL | 1 | 超过 180 秒未成功轮询 |
| `api_error` | WARN | 1 | 连续 5 次 API 请求失败 |
| `funding_opportunity` | INFO | 2 | 扣费后年化资金费收益 ≥ 10% |
| `basis_wide` | WARN | 3 | 标记价相对指数价偏离 ≥ ±0.30% |

每条规则都可以在 `config.yaml` 的 `rules:` 段单独关闭或覆盖分级、确认次数、冷却时间。

### 机会类告警（资金费 / 基差）

这一类的核心是 **只看扣费后的净收益**。

资金费套利是「做空永续 + 做多现货」的 delta 中性组合，往返要付四次手续费：
现货买入、现货卖出、永续开仓、永续平仓。按币安 VIP0 算：

```
往返成本 = 2 x (0.10% 现货 taker + 0.05% 永续 taker) + 2 x 0.03% 滑点 = 0.36%
净年化   = 毛年化 - 0.36% x 365 / 持有天数
```

持有 30 天时成本摊销 4.38%，持有 3 天时摊销 43.8%——**一个毛年化 10.95% 的机会，持有 3 天就变成负收益**。
所以 `assumed_hold_days` 是你必须按自己实际策略改的参数。

两道额外的降噪闸门：

1. **流动性过滤**：24h 成交额低于 `min_volume_usdt_24h` 的合约直接跳过。
   资金费越高的合约往往成交额越小，滑点会吃掉全部账面收益。
2. **单次扫描上限**：`max_alerts_per_scan`（默认 10）限制每类规则单次评估的标的数量。
   市场整体资金费飙升时，否则会一次产生几百条告警。

机会类告警的分级固定为 INFO，**一律走每日摘要**，不占用即时通道——
即时通道留给风险，机会信息不需要半夜叫醒你。

基差规则要特别注意：基差偏离通常伴随资金费同向偏移，但**基差本身不是可交易的收益来源**，
它的收敛时点无法预测。这条规则的价值在于提示"这里有异常定价"，而不是"这里有钱可赚"。

## 七、反噪音机制（决定这套系统能否长期活下去）

这是本系统相对现成方案的主要差异点。告警系统最常见的死法是"上线三天被噪音淹没然后被关掉"。

| 机制 | 实现 |
|---|---|
| **持续性确认** | 连续 N 次评估为真才告警，避免单次插针误报。计数在条件消失时立即清零 |
| **冷却去重** | 键为 `(规则ID, 标的, 方向)`；WARN 冷却 4 小时，CRITICAL 冷却 30 分钟 |
| **触发后重置** | 告警发出后连续计数归零，需要重新确认，避免持续条件下反复刷屏 |
| **分级路由** | CRITICAL 立即发；INFO 一律进每日摘要；WARN 在静默期或限流时进摘要 |
| **静默期** | 默认 23:30–07:00（新加坡时间）只发 CRITICAL |
| **全局限流** | 每小时最多 12 封，超出转摘要 |
| **每日摘要** | 每天 08:00 把未立即发送的告警合成一封邮件 |
| **投递失败不丢** | 立即投递失败时转入待发队列，随下一次摘要重试 |
| **心跳自监控** | 监控系统自身也被监控：轮询中断会发 CRITICAL |

## 十、已知限制（请务必了解）

1. **资金费是估算值。** 按当前费率线性外推累计，不代表实际结算金额。真实结算每 8 小时发生一次且费率会变。
   该指标用于提示成本方向，不能作为精确记账依据。
2. **维持保证金可能为估算值。** 若币安 v3 持仓接口不可用，会按 `assumed_mmr`（默认 0.5%）估算，
   邮件与快照中会标注"（估算）"。
3. **日亏损基准是进程启动后当日第一笔快照。** 如果进程在当天中途启动，当日起始权益会偏高或偏低。
   建议让进程常驻运行。
4. **回撤基准是数据库内的历史峰值。** 删除 `data/alerts.db` 会重置峰值，回撤规则需要重新积累。
5. **不支持跨保证金模式的精确风险计算。** 逐仓（Isolated）下计算最准确，建议配合交易计划书使用逐仓。
6. **只覆盖币安 U 本位合约。** 币本位（COIN-M）与杠杆账户不在范围内。
7. **告警不是交易信号。** 除非某条规则经过回测与前向验证，否则不要把它当作自动交易的触发条件。
   第十二、十三节正是这个原则的实践：资金费机会规则因回测为负期望而**默认关闭**；
   截面低波动信号虽然通过了全部统计检验，仍要求先跑前向验证再谈仓位。
8. **资金费年化是按当前费率线性外推的估算值**，不是可锁定收益。真实资金费每 8 小时结算一次且费率会变，
   趋势反转时收益可能迅速归零甚至转为支出。
9. **基差用指数价而非现货实际成交价计算。** 指数价是多家现货的加权，能反映溢价方向，
   但与你自己能成交的现货价格有差异，实际建仓成本需以盘口为准。
10. **机会扫描不含盘口深度校验。** 成交额过滤只能排除极端情况，
    真正下单前必须自己核对现货与永续两侧的盘口能否承接目标名义价值。
11. **不做跨交易所扫描。** 跨所费率差往往比单所内更值得做，但需要接入多家交易所，
    属于后续阶段（届时才会引入 `ccxt`）。

投递层——分级路由、摘要路由、单通道失败隔离、两级限流、失败转摘要队列；

## 十二、历史测算（回测）

这一节回答一个问题：**告警系统提醒的那些策略，过去一年到底赚不赚钱？**

注意区分两件事：告警系统本身只产生信息、不产生盈亏；能回测的是它提醒的策略。

### 数据来源

全部来自币安公开历史归档 `data.binance.vision`（无需 API Key、可复现、能取到已下架合约）：

- 日线 K 线：`/futures/um/monthly/klines/{SYMBOL}/1d/`，同时取现货与永续
- 资金费：`/futures/um/monthly/fundingRate/{SYMBOL}/`

缓存落在 `backtest/cache/`，删除后会自动重拉。

### 跑法

```bash
python -m backtest.run_all              # 推荐：一次跑完两半，产出合并报告
python -m backtest.run_perp_backtest    # 只跑永续方向性
python -m backtest.run_backtest         # 只跑资金费套利
```

产出：

| 文件 | 内容 |
|---|---|
| `backtest/report_all.md` | 合并报告：总览对比 + 结论 + 样本期市场状态 + 对告警系统的启示 |
| `backtest/report_perp.md` | 永续方向性详细报告（5 个策略 + 5 组敏感性） |
| `backtest/report.md` | 资金费套利详细报告（含 6 组敏感性） |
| `backtest/results_all.json` | 全部结构化结果，便于二次分析 |

### 被测算的策略

**套利类（delta 中性）**

- 做多现货 + 做空永续，盈亏 = 资金费收入 + 基差变动 − 往返手续费
- 往返成本默认 0.36%（现货 taker 0.10% × 2 + 永续 taker 0.05% × 2 + 滑点 0.03% × 2）
- 按 `成本 × 365 / 持有天数` 摊销，与资金费年化直接比较
- **按每个合约的实际结算间隔年化**（币安部分合约用 4 小时甚至 1 小时结算，硬编码 8 小时会低估一半）

**方向性类（永续）**

| 策略 | 逻辑 |
|---|---|
| `buy_hold` | 全部标的等权做多，作为基准 |
| `ma_cross` | 双均线：快线上穿慢线做多，下穿做空 |
| `donchian` | 通道突破：突破 N 日高点做多，跌破低点反手做空 |
| `funding_fade` | 资金费 z-score 极值反向 |
| `basis_fade` | 基差 z-score 极值反向 |

**统一口径**：信号用昨日收盘计算 → 今日收盘执行 → 赚今日到明日收益，各差一天，避免未来函数。
合约盈亏按 `方向 × 入场名义价值 × (出场价/入场价 − 1)`，多头最多亏光名义价值。

### 2025-09 ~ 2026-08 样本期的结果（摘要）

样本期是**深度熊市**（73 个标的等权买入持有 −67.50%，无一盈利）。初始权益 10,000 USDT：

| 策略 | 笔数 | 收益率 | 最大回撤 | 夏普 |
|---|---:|---:|---:|---:|
| 资金费套利 | 3 | −0.12% | 0.14% | −1.26 |
| 买入持有（基准） | 73 | −67.50% | 76.06% | −1.30 |
| 双均线趋势 | 26 | **+33.33%** | 16.89% | 1.04 |
| 通道突破 | 74 | +14.28% | 30.94% | 0.53 |
| 资金费极值反向 | 892 | −46.32% | 68.44% | −0.45 |
| 基差极值反向 | 1137 | −16.35% | 51.18% | −0.18 |

三条关键结论：

1. **资金费套利在这段样本里是负期望的，而且是结构性的。** 中位费率仅 0.0029%/8h（年化约 3.2%），
   而往返成本 0.36% 在 30 天持有期上要摊销掉 4.38% 的年化。按 10% 门槛全年只触发 3 笔。
2. **趋势跟踪赚钱，但盈利高度集中且全部来自空头。** 双均线利润 91% 来自 2 个标的
   （AEVOUSDT、ADAUSDT），多空拆分为多头 −1,570 / 空头 +4,903。**这更像「它做空了」，
   而不是稳定的超额收益。**
3. **两类情绪极值反向信号在所有参数下都亏钱**（z 阈值 1.0~3.0 无一为正），可直接排除。

### 进一步：边际曲线与截面策略

上面的参数扫描只能说明「某个组合不行」，不能说明「这个方向根本不行」。
因此又做了两项更根本的检验，见 `backtest/report_arb_edge.md` 与
`backtest/report_cross_sectional.md`：

**（一）资金费套利的边际曲线 —— 直接否掉了这个方向**

不找最优参数，而是测量「入场时的资金费水平 → 随后实际实现的净收益」。结果：

| 入场费率年化 | 笔数 | 平均净收益 | 中位净收益 | 胜率 | 资金费贡献 | 基差贡献 |
|---|---:|---:|---:|---:|---:|---:|
| < 0% | 9,430 | −1.471% | −0.634% | 7.9% | −1.105% | −0.006% |
| 3~5% | 3,387 | −0.361% | −0.143% | 28.8% | −0.005% | +0.004% |
| 8~12% | 3,378 | −0.668% | **+0.093%** | 58.4% | **−0.337%** | +0.029% |

两个要点：

- **高资金费不可持续。** 8~12% 那一桶里，持有期内实际收到的资金费是 **−0.337%**——
  即由「收」变成「付」。高费率不但不预测未来高费率，反而预测负费率。
- **中位数转正而均值为负**，是典型负偏态：多数交易小赚，少数被基差崩塌吃掉全部。
  这正是资金费套利被称作「在压路机前捡硬币」的原因。

25 个（信号窗口 × 持有期）组合 × 4 个成本水平 = 100 个配置，**没有任何一个**
在笔数 ≥ 30 的前提下取得正的平均净收益。按基差入场表面上出现了正期望格子，
但做去伪检查后全部倒塌：

| 持有期 | 入场基差 | 名义笔数 | 独立事件 | 名义均值 | 事件均值 | 剔除最大标的 |
|---:|---:|---:|---:|---:|---:|---:|
| 30 天 | ≥0.50% | 26 | **3** | +0.491% | +0.238% | +0.026% |
| 90 天 | ≥0.50% | 17 | **2** | +1.225% | +0.255% | **−0.834%** |

「26 笔」去重后只有 3 个独立事件，剔除 DYDXUSDT 一个标的结论就翻转。
**那是一个样本点的故事，不是统计验证。**

**（二）截面策略 —— 找到了唯一站得住的方向性来源**

时间序列策略（双均线、通道突破）在单边行情里赚的钱本质是押对了方向。
截面策略在同一时点横向比较所有标的，组合接近市场中性，理论上更不依赖大盘。
三个预先指定的截面策略结果（已计入资金费与交易成本）：

| 策略 | 收益率 | 最大回撤 | 夏普 | 夏普 90% 区间 | 留一标的 | 逐月为正 | 前 2 大标的占比 |
|---|---:|---:|---:|---|---:|---:|---:|
| `xs_momentum` | −38.07% | 43.31% | −1.06 | [−2.71, 0.62] 跨 0 | 0/73 | — | — |
| `xs_carry` | +27.02% | 13.45% | +1.29 | [−0.40, 2.85] 跨 0 | 73/73 | 6/12 | 68% |
| **`xs_lowvol`** | **+63.79%** | **11.11%** | **2.36** | **[0.76, 4.05] 不跨 0** | **73/73** | **11/12** | **24%** |

`xs_lowvol`（做多波动率最低的 5 个 / 做空最高的 5 个，每周调仓）通过了全部检验：

- 夏普 90% 置信区间不跨 0（统计显著）
- 逐个剔除任一标的，73/73 仍为正（不依赖单个标的）
- 前 2 大标的只贡献 24% 利润（不集中）
- 12 个月里 11 个月为正，最大月只占 19%（不是等一次行情）
- beta 仅 −0.17、年化 alpha +38.68%（**不是伪装的方向押注**）
- 已计入资金费（净拖累 −1,018 USDT）与交易成本

叠加组合层面波动率目标化后，目标 80% 时收益率微升至 +64.49%、**最大回撤从 11.11% 压到 7.66%**；
目标 40% 时回撤仅 4.40%，夏普基本不变（2.34 vs 2.36）——即可以在不损失风险调整收益的前提下降低风险。

`xs_carry` 虽然为正，但置信区间跨 0，属于「有迹象、未验证」，不构成自动化依据。

> **偏差声明**：样本期只有一年且为单边熊市；标的池有幸存者偏差；方向性模块已计资金费但
> 未建模借币成本与规模扩大后的滑点恶化；日线粒度看不到盘中挤空；
> 套利模块未建模永续空头腿被单独强平。
> 报告刻意不做参数寻优——敏感性分析的目的是暴露脆弱性，不是找最优参数。

## 十三、两个方向的告警规则

系统按「只提醒验证过的区间」这一原则组织规则。

### 套利方向

| 规则 | 默认 | 说明 |
|---|---|---|
| `funding_opportunity` | **关闭** | 回测为负期望。保留代码是为了可复现与将来重验；若强行开启，告警正文会带上完整的负期望证据 |
| `basis_wide` | 开启 | 基差偏离提醒，属风险信息而非收益来源 |
| `cross_exchange_funding` | 开启 | 跨所费率差。**这是套利方向唯一有结构性逻辑的候选**：它赚的是费率差（spread）而不是费率水平，不受「高费率会回归」这一结论的约束。但归档数据无法回测跨所价差，因此未经独立验证 |

### 合约（方向性）方向

| 规则 | 分级 | 说明 |
|---|---|---|
| `xs_lowvol_signal` | INFO | 截面低波动调仓信号，走每日摘要。正文强制附带回测证据块与失效条件 |
| `xs_lowvol_squeeze` | WARN | 空头腿挤空风险，走即时通道。日线回测看不到盘中挤空，必须单独监控 |

**沉默优先**：标的不够（低于 `xs_min_symbols`）时不构建半个组合，直接不出信号；
`scan_directional` 返回 `None` 时规则引擎返回空列表。宁可漏报，不可降级提醒。

```bash
python main.py directional   # 手动跑一次截面扫描，查看候选与完整证据块
```

### 前向验证：为什么回测不足为凭

一年日线只有约 250 个观测。即使夏普 2.36、bootstrap 区间不跨 0，那也只是
「在这段特定行情里我们没有找到反驳它的证据」。**统计上不足以证明正期望。**

所以每条方向性信号在发出的同时会落一条 paper trade 记录（含入场价），
到期后用真实行情回填实际结果（价格变动 + 真实资金费 − 交易成本）：

```bash
python main.py verify
```

对账报告会把前向结果与回测预期并列，并在出现下列情况时明确给出判读：

- 样本量不足 10 条 → 明说「还不足以下任何结论」
- 前向为负 → 「与回测结论冲突，应按停机条件暂停该策略，而不是给它找解释」
- 收益远低于回测 → 「不要放大仓位」

**单条记录的名义笔数会高估独立样本量。** 同一标的高度重叠的入场日，实际只是一个事件——
这正是上面资金费套利「26 笔 → 3 个独立事件」的教训。

## 十四、投递通道（SMTP 邮件 + Telegram）

通道配置在 `config.yaml` 的 `notify.channels`，URL 一律从环境变量读取，不落盘：

```yaml
notify:
  channels:
    - name: telegram
      url_env: APPRISE_TELEGRAM_URL      # tgram://<bot_token>/<chat_id>
      severities: [CRITICAL, WARN]       # 机会类 INFO 不进 Telegram
      digest: false
    - name: email
      url_env: APPRISE_EMAIL_URL         # mailtos://用户:应用密码@gmail.com?to=收件人
      severities: [CRITICAL, WARN, INFO]
      digest: true
```

设计要点：

- **分级路由**：风险走 Telegram 即时通道，机会信息只进邮件摘要——不该半夜把人叫醒。
- **失败隔离**：单通道异常或返回失败不影响其他通道；全部失败时告警转入摘要队列，
  避免静默丢失。
- **两级限流**：全局限流（存库、跨重启有效）+ 通道级限流（进程内），防止告警风暴。
- **未配置的通道静默跳过**：只填了 Telegram 没填邮件密码时，Telegram 照常工作。
- 若 `notify.channels` 整个为空，回退到旧的单一 `APPRISE_URL`。

Telegram 的 `chat_id` 获取方式见 `.env.example` 的注释。
